The building, the flat and the phone book

To send a letter you need an address. A computer on the internet has one too. It is called an IP address, like the address of a big apartment building.

But a building has many flats. The port is the flat number: it tells the letter which program inside the computer should get it. Web pages go to one flat, the database goes to another.

Now, you do not remember the IP address of your friend's house; you save the name in your phone. DNS is the internet's phone book. You say google.com; DNS says the number.

IP, ports and DNS

IP address

Every device that talks on the internet has a number. Two kinds exist:

The two example numbers above are only to show the shape. Real addresses change.

Public vs private IP. A public IP can be reached from anywhere on the internet; servers need one. A private IP only works inside a local network (your home Wi-Fi, an office, a company's cloud network). Common private ranges start with 192.168., 10. or 172.16. to 172.31.. Your phone and laptop at home usually have private IPs, and the router shares one public IP for all of them.

Ports

An IP address finds the computer. A port (a number from 0 to 65535) finds the program on it. Together they look like 203.0.113.10:443. Ports you should know:

PortUsually used for
80HTTP (plain websites)
443HTTPS (secure websites)
5432PostgreSQL database
3000A common default for local dev servers, such as Next.js or Express

Browsers add port 80 or 443 for you, which is why you never type it.

DNS: name to number

Computers talk in IP addresses, people remember names. DNS (Domain Name System) converts www.example.com into an IP. Looking it up is called resolving. Asking everyone every time would be slow, so the answer is cached at several levels. The chain, from nearest to farthest:

  1. Browser cache: "I looked this up a minute ago."
  2. Operating system cache (and the hosts file).
  3. Recursive resolver: a helper run by your internet provider, or a public one such as 8.8.8.8 or 1.1.1.1. It does the legwork for you and caches results.
  4. Root server: knows who handles .com, .in, and so on.
  5. TLD server (top-level domain, e.g. .com): knows who handles example.com.
  6. Authoritative server: the final owner of the records for that domain. It gives the real answer.

Steps 1 to 3 usually finish it. Steps 4 to 6 only happen when nobody has the answer cached.

Record types

RecordMeaning
AName to IPv4 address
AAAAName to IPv6 address
CNAME"This name is an alias of that other name"
MXWhich mail servers accept email for this domain
TXTFree text; used for proofs such as "I own this domain" and email security settings

TTL (time to live) is a number of seconds on each record: how long others may cache the answer.

Trade-offs

  • Long TTL (say a day): fewer lookups, faster for users, cheaper. But if you move your server to a new IP, some users keep going to the old one until the cache expires.
  • Short TTL (say 60 seconds): changes spread fast, which helps for failover. More lookups happen.

Practical habit: before planning to move a site to a new server, lower the TTL a day earlier. Then the switch is quick.

"DNS issue" is a classic cause of "the site is down for some people but not others". Different resolvers can be holding different cached answers.

Do it yourself (about 25 minutes)

A. Open Command Prompt

  1. Press the ⊞ Win key, type cmd, and press Enter. A black window with a blinking cursor opens. That is Command Prompt. (It may open inside Windows Terminal; that is fine.)
  2. To paste something you copied from this page: Ctrl + V works, or right-click inside the window (in Windows Terminal, right-click pastes). Then press Enter to run it. Or just type the commands yourself.

B. Find your own address

ipconfig
  1. Type it, press Enter. A list of network adapters appears.
  2. Find the one for Wi-Fi (it says Wireless LAN adapter Wi-Fi) or Ethernet. Look at IPv4 Address. It will most likely begin with 192.168. or 10.: that is your private IP.
  3. You may also see Default Gateway. That is your router.
  4. Your public IP is different. To see it, in Chrome search "what is my IP". It will not match the one from ipconfig.

C. Ask DNS for an address

nslookup google.com
  1. Run it. The top lines show which DNS server answered (your resolver).
  2. Below, a line says Non-authoritative answer (this just means the answer came from a resolver's cache, not directly from the owner), followed by Name and Address lines. Those are Google's IPs. You may see an IPv6 one and an IPv4 one.
  3. Run it again. The addresses may be the same or different; big sites hand out several.

D. Ask for the mail servers

nslookup -type=mx gmail.com
  1. You should see lines containing MX preference and mail exchanger followed by names. These are the servers that accept email sent to @gmail.com. The lowest preference number is tried first.
  2. Optional: try nslookup -type=txt gmail.com to see TXT records.

E. Ping

ping google.com
  1. Run it. Four lines appear like Reply from ... time=XXms. Each is a tiny message to the server and back, and time is the round trip in milliseconds.
  2. Note the IP it printed. It is what DNS returned. If it says "Request timed out", the site may block ping; that is normal for some sites. Try another one.
  3. You just did, by hand, what your browser does silently every time.

Quick quiz

What is the difference between an IP address and a port?

The IP finds the computer; the port finds the program inside it.

Which ports do HTTP, HTTPS and PostgreSQL usually use?

80, 443 and 5432.

List the DNS resolution chain in order.

Browser cache, OS cache, recursive resolver, root server, TLD server, authoritative server.

What is a CNAME record?

An alias: it says one name is another name, so you look up that other name instead.

You are moving your site to a new server next week. What do you do with the TTL, and why?

Lower it a day or so before the move (say to 60 seconds or a few minutes), so caches forget the old IP quickly. After the move is stable, raise it again to reduce lookups.

Say it in an interview

"DNS translates a domain name to an IP address. The answer is cached at the browser, the OS and the resolver, and the TTL decides how long."
"An IP address finds the machine and a port finds the process on it; HTTPS is 443 and Postgres is 5432."

Common follow-up question: A user reports your site is down but it works for you. Could DNS be the reason?

Yes. If we recently changed the DNS records, different resolvers may still cache the old IP until the TTL expires, so some users reach the new server and others the old one. I would check with nslookup against different resolvers, and I would lower the TTL before future changes.
